# 申込のDiscord連携

スプレッドシートに溜まった申し込みをDiscordへ流し、承認されたものに連絡とロール付与を行う。
手元のPCでコンテナとして動かし続ける。

全体の流れは `../README.md` にある。先にそちらを読む。
Apps Script 側は `../form_to_discord/` にある。

## どちらがどの列を書くか

列が空のときだけ処理する。両方が同じ列を書くことはない。

| 列 | 書くのは | 何を表すか |
|---|---|---|
| 受付番号 | Apps Script | 採番した番号 |
| 受付メール送信 | Apps Script | 受付メールを送った時刻 |
| discord自動投稿 | コンテナ | スタッフ専用チャンネルへ投稿した時刻 |
| 申込投稿ID | コンテナ | その投稿のID |
| 承認確認 | コンテナ | `:yosasou:` が必要数に届いた時刻 |
| 採択メール送信 | Apps Script | 採択メールを送った時刻 |
| 採択メール確認 | コンテナ | `:mail_done:` を付けた時刻 |
| 採択discord送信 | コンテナ | 一般向けチャンネルへ投稿した時刻 |
| 採択投稿ID | コンテナ | その投稿のID |
| DiscordユーザーID | コンテナ | 申込者と判定したアカウントのID |
| ユーザー未特定通知 | コンテナ | 申込者が見つからないと知らせた時刻 |
| ロール付与 | コンテナ | ロールを付けた時刻 |
| OKリアクション確認 | コンテナ | 申込者が 🆗 を付けた時刻。申込投稿に `:ok_done:` を付ける |

`:yosasou:` は通常のリアクションで付ける。スーパーリアクションは数に入らない。
1人が両方を付けて2件に見えるのを防ぐため、通常のリアクションだけを数えている。

## 企業スポンサーへ送るメールの下書き

企業スポンサーには承認の仕組みが無く、確定の連絡はスタッフが手で送る。
申し込みの内容で要る節が変わるので、下書きを組み立てて申込投稿のスレッドに出す。
スタッフはそれをコピーしてメールに貼る。

申込投稿と同時にスレッドが作られる。スレッドの名前は `SPONSOR-001 会社名` の形。
出し分けは次のとおり。

| 節 | 出す条件 |
|---|---|
| ロゴ (前回のものを使用) | 「ロゴについて」が `以前と同じでOK` |
| ロゴ (新しくご提供) | 「ロゴについて」が `Discordにてやりとり` |
| スポンサーLTのご発表 | 特典に `スポンサー枠LT発表` |
| スポンサーピッチ | 特典に `スポンサーピッチ` |
| スライド配信 (前回のものを使用) | 特典に `スライドの配信` かつ「スライドについて」が `以前と同じでOK` |
| スライド配信 (新しくご提供) | 特典に `スライドの配信` かつ「スライドについて」が `Discordにてやりとり` |
| チラシ・ノベルティ (事前発送) | 受け渡し方法が `事前発送` |
| チラシ・ノベルティ (当日搬入) | 受け渡し方法が `当日搬入` |
| connpass のお申し込み | 常に |
| スポンサー費用 | 常に |

「以前と同じでOK」を選んだ会社には、前回のロゴのURLを載せる。
URLは `src/config.py` の `SPONSOR_LOGO_URLS` に会社名で引く表がある。
表に無い会社には「前回のロゴが見つかりません」と出る。新しく申し込んだ会社は毎年足す。

文面の中の日付とURLも毎年直す。`src/sponsor_mail.py` の先頭に近いところにまとまっている。

## スタッフを呼び出す投稿

人が手を動かさないと進まないものだけ `@コアスタッフ` を付ける。

| 投稿 | 呼び出し |
|---|---|
| 新しい申し込みが届いた | 付く |
| 処理に失敗した | 付く |
| 確認してほしい | 付く |
| 申込者が見つからない | 付く |
| 処理が進んだ記録 (ログ用チャンネル) | 付かない |

## 用意するもの

### サービスアカウント

スプレッドシートを読み書きするために使う。課金アカウントの登録は要らない。

1. `https://console.cloud.google.com` でプロジェクトを作る
2. 「APIとサービス」→「ライブラリ」で `Google Sheets API` を有効にする
3. 「認証情報」→「認証情報を作成」→「サービス アカウント」。ロールの割り当ては飛ばす
4. 作ったサービスアカウントの「キー」タブ →「鍵を追加」→「新しい鍵を作成」→ JSON
5. ダウンロードしたファイルを `secrets/service_account.json` に置く
   - `secrets/` は git に入っているので、clone すれば既にある
   - 無い状態で `docker compose up` すると、Docker が root 所有で作る。そうなったら
     `docker compose down` してから `sudo chown -R $USER:$USER secrets` で戻す
6. スプレッドシートの「共有」で、JSONの中の `client_email` を**編集者**として追加する

鍵のファイルは `secrets/` に置く。このディレクトリは git に入らない。

プロジェクトは Google Workspace の組織の中に作った。
そのため、組織の外のアカウントと `@googlegroups.com` のグループを権限に追加できない。
組織のポリシーで、外のドメインを足せないようになっている。

引き継ぐときは次のどちらかになる。

- 同じ Workspace の中のグループに「オーナー」を渡す
- 次の担当者に Workspace のアカウントを用意し、個人として「オーナー」を渡す

Workspace を解約すると、このプロジェクトごと触れなくなる。
そのときは新しいプロジェクトとサービスアカウントを作り直し、鍵を入れ替える。

### Discord の Bot

1. `https://discord.com/developers/applications` で「New Application」
2. 「Bot」タブで「Reset Token」を押し、出たトークンを控える。この画面を閉じると二度と見られない
3. 同じ画面の「Privileged Gateway Intents」で `SERVER MEMBERS INTENT` をオンにする
   - 申込者のアカウントを名前で探すのに要る。オフだと誰も見つからない
4. 「OAuth2」タブで `bot` にチェックし、権限は次の6つ
   - `View Channels`
   - `Send Messages`
   - `Create Public Threads`
   - `Send Messages in Threads`
   - `Add Reactions`
   - `Manage Roles`
5. 出てきたURLを開き、NGKのサーバーを選んで招待する
6. サーバー設定の「ロール」で、Bot のロールを、付与する5つのロールより **上** に動かす
   - 下にあると「自分より上のロールは付けられない」と断られる
7. 使う7つのチャンネルそれぞれで、Bot のロールに閲覧と送信を許す

トークンは `.env` にだけ書く。チャットや画面共有に出さない。

### 設定ファイル

`env.example` を `.env` という名前でコピーし、空の項目を埋める。

```
cp env.example .env
```

埋めるのは `DISCORD_BOT_TOKEN` と `SPREADSHEET_ID` の2つ。ほかは値が入っている。

## 動かす

先に Apps Script 側の `setUp` を実行しておく。管理列を作るのは Apps Script の役目で、
列がそろうまでコンテナは「管理列がありません」を出し続ける。

```
docker compose up -d --build
```

動いているかを見る。

```
docker compose ps
docker compose logs -f
```

止める。

```
docker compose down
```

設定や文面を直したあとは、作り直して入れ替える。

```
docker compose up -d --build
```

## 本番の申し込みに触らずに試す

`.env` の `ONLY_NUMBERS` に受付番号を書くと、その行しか処理しない。
既に申し込みが入っている状態で動きを確かめるときに使う。

```
ONLY_NUMBERS=TEST-1,TEST-2,TEST-3,TEST-4,TEST-5,TEST-6
```

### 試す行を作る

受付番号は `TEST-` で始める。採番は `LT-` `COMMUNITY-` `SPONSOR-` で始まる行しか見ないので、
`TEST-` なら次の番号が狂わない。

どのシートに置くかで、どのフォームの申し込みとして扱われるかが決まる。
文面が変わる組み合わせは6通りある。

| 受付番号 | シート | 入れる値 | 何を確かめるか |
|---|---|---|---|
| TEST-1 | LT発表申込 | 申込み種別 = 一般LT | 一般LTの採択メールと投稿 |
| TEST-2 | LT発表申込 | 申込み種別 = コミュニティLT | コミュニティLTの採択メールと投稿 |
| TEST-3 | LT発表申込 | 申込み種別 = スポンサーLT | 採択ではなく受付の連絡になること |
| TEST-4 | コミュニティ参加申込 | 参加形態 = ロゴ掲載とLT、ロゴ・スライド等 = Discord上でやりとり | 画像とLTの両方をお願いする文、ロゴとLTの詳しい案内 |
| TEST-5 | コミュニティ参加申込 | 参加形態 = ロゴ掲載、ロゴ・スライド等 = 以前と同じでOK | 昨年のものを使う文、詳しい案内が出ないこと |
| TEST-6 | 企業スポンサー申込 | 希望するプランを選ぶ | 投稿だけで終わること、請求先が出ないこと |

どの行にも次の3つを入れる。

| 列 | 入れる値 |
|---|---|
| 受付番号 | `TEST-1` など |
| 受付メール送信 | 何か文字。空だとApps Scriptが受付メールを送る |
| Discord ユーザー名 | 自分のDiscordユーザー名 |

メールアドレスの列には自分のアドレスを入れる。採択メールがそこへ届く。

### 動かす

1. `.env` に `ONLY_NUMBERS=TEST-1,TEST-2,TEST-3,TEST-4,TEST-5,TEST-6` を書く
2. `docker compose up -d --build` で起動する
3. ログに「試しの設定が入っています」と出るのを確かめる
4. スタッフ専用チャンネルに6件の投稿が出る
5. TEST-1 から TEST-5 に `:yosasou:` を2つ付ける
6. 採択メールが自分に届き、一般向けチャンネルに投稿が出て、ロールが付くのを見る
7. その投稿に 🆗 を付け、「OKリアクション確認」に時刻が入るのを見る

TEST-6 は投稿だけで終わる。承認の仕組みがないため。

ついでに `:horyu:` も試せる。どれか1件に `:horyu:` と `:yosasou:` を2つ付けて、進まないことを見る。
外せば次の回に進む。

### 片付ける

1. 付いたロールを自分から外す
2. Discordの投稿を消す。スタッフ専用チャンネル、一般向けチャンネル、ログ用チャンネルの3か所
3. スプレッドシートの `TEST-` の行を消す
4. `.env` の `ONLY_NUMBERS` を空にする
5. `docker compose up -d --build` で作り直す

**4を忘れると、本番の申し込みが処理されないまま溜まる**。
起動のたびにログへ知らせが出るので、そこで気づく。

## PCを再起動しても動くようにする

Docker 自体が自動で起動するようにしておく。コンテナは `restart: always` を指定してあるので、
Docker が起動すれば一緒に立ち上がる。

```
sudo systemctl enable --now docker
```

一度 `docker compose up -d` で起動しておけば、以降は再起動のたびに自動で立ち上がる。
確かめるには、PCを再起動してから `docker compose ps` を実行する。

## 止まっていないかを確かめる

スプレッドシートに「実行状態」というシートができる。B1に最終実行時刻が入る。
数時間更新されていなければ止まっている。

```
docker compose ps
docker compose logs --tail 50
```

## 何がどこに記録されるか

| どこ | 何を残すか |
|---|---|
| 標準出力 (`docker compose logs`) | 受付番号と処理名だけ。名前もメールアドレスも出さない |
| Discord のログ用チャンネル | 受付番号、名前、処理名、投稿へのリンク |

標準出力はPCのディスクに残り続けるので、受付番号で追う形にしている。
ログ用チャンネルはスタッフしか見られないので、誰についての記録かが分かるよう名前を出す。

| フォーム | ログに出る名前 |
|---|---|
| LT発表申込 | 発表者名 |
| コミュニティ参加申込 | コミュニティ名 / 担当者名 |
| 企業スポンサー申込 | 会社名 |

メールアドレスはどこにも出さない。スプレッドシートで見る。

ログを残せなかったときは、その行の処理を止める。記録が欠けたまま進むと、何が済んだか追えなくなる。

## 止まったときに戻す手順

スタッフ専用チャンネルに失敗の知らせが出たら、スプレッドシートのその行を見る。

| 空になっている列 | 直し方 |
|---|---|
| 受付番号 | 何もしない。送信から10分たった回で拾い直す |
| 受付メール送信 | 手でメールを送り、列に時刻を書く |
| discord自動投稿、申込投稿ID | 何もしない。次の回でやり直す |
| 承認確認 | 何もしない。次の回でやり直す |
| 採択メール送信 | Apps Script 側の問題。実行ログを見る |
| 採択メール確認 | 何もしない。次の回でやり直す |
| 採択discord送信 | 何もしない。次の回でやり直す |
| 採択投稿ID | 投稿は届いている。OKリアクションの確認だけができない。投稿のIDを手で書く |
| ロール付与 | 何もしない。次の回でやり直す |

「採択discord送信の取り消し」の知らせが出たときだけ、手で直す。
一般向けチャンネルを見て、投稿が無ければ「採択discord送信」を空にする。

申込者への連絡は、送る前に列へ印を立ててから送る。
送れなかったときは印を消してやり直す。印を消すのにも失敗したら、その行は止まって知らせが出る。
同じ連絡が2回届くより、止まって気づけるほうを選んでいる。

次の3つは、知らせに書かれた指示に従う。

| 知らせの内容 | 直し方 |
|---|---|
| 申込投稿が見つかりません | 「申込投稿ID」と「discord自動投稿」を空にする。次の回に投稿し直す |
| Discordユーザーが見つかりません | 申込者の参加を待つ。待たずに手で済ませるなら、「採択discord送信」と「ロール付与」に時刻を書く |
| DiscordユーザーIDが読めません | その列と「採択discord送信」「採択投稿ID」を空にする。申込者を探すところからやり直す |

ログ用チャンネルに「管理列がありません」が出たときは、Apps Script 側の `setUp` を実行する。
この知らせはコンテナが動いている間に1回だけ出る。

「承認確認」の時刻を消すと、承認の検知からやり直す。
「採択メール送信」に時刻が入っているときに消すと、同じメールが2回届く。

手でロールを付けたときは「ロール付与」に時刻を書く。
書かないと、次の回にコンテナがもう一度付けようとする。

## 途中から入れ替えるとき

一度動かしたあとでコードを入れ替える場合は、先にスプレッドシートを確かめる。

- 「DiscordユーザーID」列に17桁から19桁の数字が入っているか。末尾が `000` や `1.5E+18` の形なら
  数値に化けている。その行の「DiscordユーザーID」「採択discord送信」「採択投稿ID」を空にする
- 手でロールを付けた行の「ロール付与」に時刻が入っているか。空だとコンテナがもう一度付けようとする

化けた値を空にしないまま動かすと、スタッフ専用チャンネルに「DiscordユーザーIDが読めません」が出る。

## 来年へ引き継ぐとき

渡すもの。

| もの | 置き場所 |
|---|---|
| Discord Bot のトークン | 団体のパスワード管理 |
| サービスアカウントの鍵 | 同上 |
| Discord Bot アプリの所有者 | Discord Developer Portal |
| Google Cloud のプロジェクト | 団体のアカウント。外のグループは足せない。「サービスアカウント」の節を見る |
| スプレッドシートの所有者 | 団体のアカウント |

毎年やること。

- チャンネルID、ロールID、絵文字IDを新しい年のものに差し替える (`env.example` と `.env`)
- 文面の年号と日付を直す (`src/messages.py` と `scripts/form_to_discord/Messages.gs`、`messages.md`)
- Bot のトークンとサービスアカウントの鍵を作り直す
- フォームの質問文を変えたら、`src/config.py` と `Config.gs` の列名も直す
- Discord の招待リンクは Apps Script のスクリプトプロパティに入れる。`.env` には入れない

## 気をつけること

- **コンテナは1つだけ動かす。2つ以上に増やさない**。同じ行を2つが同時に処理すると、同じ連絡が2回届く。1つだけなら順番に処理するので重ならない
- 行を並べ替えない。消さない。管理列の値と行の対応が崩れる
- 受付番号は、その列に入っている最大値に1を足して作る。手で番号を書き足さない
- スタッフ専用チャンネルには申込者のメールアドレスを出していない。受付番号で追う
- `.env` と `secrets/` は `.gitignore` で除外してある。ただし除外が効くのは `.gitignore` 自体を
  コミットした後から。このリポジトリは公開なので、新しく追加するときは必ず先に
  `git ls-files --others --exclude-standard scripts/` で、入るファイルの一覧を目で確かめる
