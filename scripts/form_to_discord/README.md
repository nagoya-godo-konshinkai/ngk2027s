# 申込フォームの受付処理

Googleフォームに届いた申し込みに受付番号を振り、受付メールを送る。
承認された申し込みには採択メールを送る。

全体の流れは `../README.md` にある。先にそちらを読む。
Discord への投稿、承認の検知、ロール付与は `../discord_sync/` のコンテナが行う。

## このスクリプトがやること

フォームが送信されたとき

1. 受付番号を採番する
2. 申込者へ受付メールを送る
3. 「受付番号」と「受付メール送信」の列に書く

1分おき

1. 「タイムスタンプ」に値があり「受付番号」が空の行を探し、受付をやり直す
2. 「承認確認」に時刻が入り、「採択メール送信」が空の行を探す
3. 「採択メール送信」の列に時刻を書く
4. 申込者へ採択メールを送る。送れなかったら 3 で書いた時刻を消す

送る前に時刻を書くのは、送った後で書けなかったときに同じメールが2通届くのを防ぐため。
送れず時刻も消せなかった行は止まる。Google からの通知メールで気づく。

1 は取りこぼしの救い上げ。フォーム送信のトリガーが落ちると、その申し込みは受付番号が
振られないまま埋もれる。受付番号を見分けの印にしているので、空の行は誰からも拾われない。
送信から10分は手を出さない。トリガーが遅れているだけの行を拾い直すと、
同じ受付メールが2通届く。

承認したかどうかの判断と、Discord の操作はコンテナ側が行う。

3つのフォームでは「回答の編集を許可する」を切ってある。
申込者が送信後に内容を書き換えられると、スタッフが見て承認した内容と食い違う。
この設定を入れると、承認した内容と実際の内容がずれる経路そのものが無くなる。

## ファイル

| ファイル | 中身 |
|---|---|
| `Config.gs` | シート名、列名、受付番号の形 |
| `Messages.gs` | メールの文面 |
| `Sheet.gs` | 回答シートの読み書き |
| `OnSubmit.gs` | フォーム送信の直後の処理 |

| `messages.md` | メールとDiscord投稿の文面を人が読む形で並べたもの |

## スプレッドシートの準備

3つのフォームの回答先を1つのスプレッドシートにまとめる。
各フォームの「回答」から「スプレッドシートにリンク」を開き、既存のスプレッドシートを選ぶ。

シート名を下の3つに合わせる。違う名前にしたいときは `Config.gs` の `SHEET_NAMES` を直す。

- `LT発表申込`
- `コミュニティ参加申込`
- `企業スポンサー申込`

フォームの質問文を変えたら `Config.gs` の `COL_LT` `COL_COMMUNITY` `COL_SPONSOR` も直す。
`checkSettings` を実行すると、見つからない列を実行ログに出す。
`printHeaders` を実行すると、ヘッダの文字列を改行も含めてそのまま出す。

## スクリプトプロパティ

スプレッドシートの拡張機能から Apps Script を開き、プロジェクトの設定でスクリプトプロパティに入れる。

| 名前 | 入れる値 |
|---|---|
| `DISCORD_INVITE_URL` | Discord サーバーの招待リンク。採択メールに載せる |

## コードを送り込む

`clasp` を使う。画面にコピーして貼る必要はない。

```
cd scripts/form_to_discord
npx @google/clasp login
npx @google/clasp push
```

`login` はブラウザが開く。スプレッドシートを持っているアカウントで、
「Google Apps Script のプロジェクトの作成と更新」だけを許可すれば足りる。

先に `https://script.google.com/home/usersettings` で Google Apps Script API をオンにする。
ブラウザで複数のアカウントにログインしていると、別のアカウントの設定をオンにしてしまうことがある。

送り先は `.clasp.json` に書いたスクリプトID。このファイルは `.gitignore` に入れてある。

`push` は Apps Script 側のファイルを丸ごと置き換える。
画面で直接直したものは消えるので、直すときはローカルのファイルを直して push する。

## 動かすまでの手順

1. `npx @google/clasp push` でコードを送る
2. スクリプトプロパティに `DISCORD_INVITE_URL` を入れる
3. `checkSettings` を実行し、設定と列を確かめる
   - 求める権限が変わっているので、ここで承認し直す画面が出る
4. `setUp` を実行する。管理列が足され、トリガーが2つ作られる
   - **既に申し込みが入っているシートで実行すると、1分後に全行へ受付メールが送られる**
   - 受付番号が空の行を「トリガーが落ちた取りこぼし」とみなすため
   - 既存の行があるときは、先に「受付番号」と「受付メール送信」を手で埋めておく
   - 作ったあと、「トリガー」画面で両方の通知設定を「今すぐ通知」に変える
   - 既定では1日1回にまとまる。止まったことに気づくのが翌日になる
5. フォームに試し送信し、受付メールが届くのを見る
6. そのあとコンテナを起動する (`../discord_sync/README.md`)

管理列を作るのは `setUp` の役目。先にコンテナを動かすと、列がそろうまで
「管理列がありません」を出し続ける。

## 運用するときの注意

- 行を並べ替えない。消さない。管理列の値と行の対応が崩れる
- 同じ名前の列を2つ作らない。`checkSettings` が見つけたら知らせる
- 受付番号は、その列に入っている最大値に1を足して作る。手で番号を書き足さない
- メールの差出人は、このスクリプトを置いたアカウントのアドレスになる。表示名だけ「NGK実行委員会」にそろえている
- 宛先は1つのメールアドレスの形でないと送らない。カンマで複数書かれた回答は弾く
- Google Workspace のアカウントは1日1500通まで送れる。無料のアカウントは100通
- 処理が止まると Google から通知メールが届く
- フォームの「メールアドレス」の質問には、回答の検証でメールアドレス形式を設定しておく

## 文面を直すとき

メールの文面は `Messages.gs`、Discord 投稿の文面は `scripts/discord_sync/src/messages.py` にある。
`messages.md` は両方を読みやすく並べたもの。直したら反映する。
